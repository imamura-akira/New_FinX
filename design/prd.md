## 1. 背景与目标

面向华语用户的美股交易 App，券商基础设施由 DW 提供（账户托管、清算、KYC、资金）。本阶段不追求功能完整，只验证"一个真实用户能在沙盒里走完从注册到出金的全部环节"，为第二阶段（行情、交易、生产接入）打基础。

**本阶段成功标准（DoD）**：在 DW UAT 沙盒中，用 App 完成以下连续流程且状态在 App 内正确展示——
1. 邮箱验证码注册登录（Google / Apple 可后置到阶段 1.5）；
2. 填写开户资料并提交，后端成功创建 DW User（POST + PATCH 两步）；
3. KYC 状态流转在 P-06 正确展示；P-34 / P-35 / P-36 至少各触发验证一次（触发方式待 Q-DW-5）；
4. KYC 通过后自动开立 LIVE / CASH / SELF 账户，账户号码在 App 内可见；
5. 绑定银行账户（方式按 Q-DW-2 答复）并完成一笔 ACH 入金，状态到 SUCCESSFUL；
6. 获取电汇入金指引（deposit-instructions）并正确展示；
7. 发起一笔 ACH 出金，可提现金额与 DW 返回一致；
8. SQS 事件（或轮询对账）驱动上述状态更新，App 不直接调用 DW。
9. 首页展示来自 DW 的真实账户余额，且在一笔入金到账后数值变化可见；
10. 行情页与自选显示虚拟行情，且价格在观察期间内可见地变动（非静态数据）。

## 2. 范围

### 2.1 本阶段做
- 登录注册（邮箱 OTP 为主）、会话管理。
- 开户全流程（P-01–P-06、P-30、P-34–P-36），资料暂存与续填。
- 资金账户与出入金（P-13、P-14、P-31、P-32、P-33），交易记录时间线（P-18 的资金部分）。
- 账户状态与受限展示（P-06、P-08、S-01）。
- 通知（P-17 的账户/资金类，站内即可，推送后置）。

### 2.2 本阶段不做（已在 UI 中占位或标注）
- 真实行情源与交易下单（P-09–P-12、P-19–P-24 的**展示**接后端虚拟行情服务，见 F11；下单不做）。
- P-25 智能组合；P-26 AI 助手（待合规评估）、P-27 奖励的真实功能（v1.1：P-23/P-24、P-26、P-27 以模拟数据展示版式，见 F13）。
- ACATS 转入（P-28，仅页面）。
- 生产环境接入、真实资金、推送、多语言。

## 3. 用户与核心场景

- **美国纳税人（SSN/ITIN）**：资料 + SSN → DW 数据库核验，通常无需证件；ACH 为主。
- **非美国纳税人**：资料 + 护照等证件上传 → 核验（常走人工复核）；电汇为主（无美国银行账户）。
- 异常场景：资料被标记（P-34）、需补证件（P-35）、被拒（P-36）、入金被退回、账户冻结/仅可卖出。

## 5. 非功能需求

- **安全**：DW 凭据仅存后端环境变量；PII 字段级加密存储；证件影像加密、最小留存（法务定期限，问题 15）；App 不出现任何 DW 凭据与真实账户编号。
- **可用性**：后端对 DW 调用全部异步化 + 重试；token 缓存（请求预算约 5–10 次/小时）；事件消费失败有轮询对账兜底。
- **视觉与文案**：Flutter 主题与品牌素材以 `design/theme.md` 为唯一基准（FinX 紫罗兰主题、Fifi 素材）；开户/KYC 模块英文文案直接取自原型，不另行翻译。
- **可配置**：ui-signoff.md 第 2 节的 5 个开关全部走配置，拿到 DW 答复只改配置与文案。
- **可观测**：每次 DW 调用记录 requestId / 响应码；KYC 与资金状态变更留审计日志。

## 6. 里程碑（建议）

| 里程碑 | 内容 | 出口条件 |
|---|---|---|
| M0 | 向 DW 提交 Q-DW 问题单；后端骨架 + token 缓存跑通 | 沙盒 token 获取成功；Q-DW-1/2 已提交 |
| M1 | F1–F4：注册→提交开户→KYC 状态展示 | 沙盒创建 User 成功，状态在 App 展示 |
| M2 | F5–F6：补救流程 + 开户 | P-34–P-36 验证；账户 OPEN |
| M3 | F7–F9：绑卡 + 入金 + 出金 | 一笔 ACH 入金 SUCCESSFUL、一笔出金成功 |
| M4 | F10 + 对账与审计 + DoD 全流程演练 | 第 1 节 DoD 全部通过 |

## 7. 风险与依赖

- **Q-DW-1（KYC 模式）**：若非 Do KYC，F4/F5 与 3.2.1 数据流需重写 —— M1 前必须拿到答复。
- **Q-DW-2（绑卡方式）**：决定 F7 实现与 P-32 形态 —— M3 前必须拿到答复。
- 沙盒行为与文档不一致的风险：以沙盒实测为准，差异回写 pages.md 变更记录。
- 合规：本 PRD 不代表合规通过；生产前需 DW 24 项签核与法务审核。
